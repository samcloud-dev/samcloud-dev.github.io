A locked-down home for FreshTrack, built entirely from code

I'm Samson, a DevOps Engineer. Over eight build days I wrote Terraform that creates a small AWS platform in Canada for FreshTrack, my household food-expiry app. One command builds it, Ansible configures the server through AWS Systems Manager with no SSH, and one command removes it so it costs nothing between sessions.

Eight days, one layer at a time

Every day ended the same way: predict the plan, apply, verify three ways (Terraform output, Terraform state, AWS CLI), open a pull request, then destroy.

  1. Day 1foundation

    Project, provider, a VPC

    Pinned Terraform and the AWS provider, default tags on every resource, state kept out of Git, short-lived logins instead of permanent keys.

    init → fmt → validate → plan → apply → verify
  2. Day 2network

    Four subnets across two Availability Zones

    Asked AWS for the zone names instead of guessing (this region has no 1c). Fixed a 403 on git push by switching to SSH.

    public 10.0.1/2 · private 10.0.11/12
  3. Day 3routing

    Internet gateway and route tables

    Public subnets get a road to the internet; private subnets only route inside the VPC. NAT deferred to save cost.

    7 resources, plan matched prediction
  4. Day 4first server

    EC2 host behind a security group

    First server fully from code. Reviewed SonarCloud's public-IP finding and accepted it with a written reason.

    web page served, then destroyed
  5. Day 5hardening

    No SSH, protected metadata, encrypted disk

    IAM role with only the Systems Manager policy, IMDSv2 required, encrypted gp3 root volume.

    SSM login as ssm-user · IMDS 401 without token · Encrypted: True
  6. Day 6state

    Remote state in S3 with locking

    A separate bootstrap project builds a versioned, encrypted, HTTPS-only bucket that is never destroyed. State migrated off my laptop.

  7. Modulesrefactor

    Subnet ranges computed with cidrsubnet(), names prefixed by project and environment, input validation, provider requirements declared. Review caught an empty versions.tf that validate missed.

    Right-sized, locked door, fixed address

    Instance type and disk as variables, ports 80/443 open to my IP only (kept out of the public repo), an Elastic IP, old nginx setup removed.

    Ansible through Systems Manager

    Learned Ansible on my laptop first, then ran the same playbooks on the EC2 host through SSM with an S3 transfer bucket. Proved the host needs no S3 permission.

    first run changed=2 · second run changed=0
Security

Defence in layers

  • 01
    No SSH, no keysPort 22 stays closed. Admin access and Ansible both go through Systems Manager, and sessions are audited.
  • 02
    A door for one addressPorts 80 and 443 accept only my /32 until FreshTrack has HTTPS and basic auth. The IP lives in a git-ignored tfvars file.
  • 03
    Least privilege, testedThe host's IAM role has only the SSM policy. I tested Ansible without S3 rights first; it worked through pre-signed links, so none were added.
  • 04
    Protected metadataIMDSv2 required with hop limit 1, so stolen-credential tricks through the metadata service fail.
  • 05
    Encrypted everywheregp3 root disk, both S3 buckets, and HTTPS-only bucket policies (an explicit deny beats any allow).
  • 06
    Reviewed changesEvery change goes branch → pull request → SonarCloud. Findings are fixed or accepted with a written reason.
Cost

Paying only while it runs

The stack is destroyed after every session, so idle cost is close to zero. The Elastic IP is released with it, and the domain name will be the stable address. A small t3.small is used while learning; the 8 GB m7i-flex.large is chosen with one flag only when k3s needs it. No NAT gateway and no load balancer until the scaling ladder calls for them.

What's next

From platform to a live household trial

Day 9 · k3s

Ansible installs k3s on the 8 GB host. kubectl reaches it through SSM port forwarding, with 6443 kept closed. Guards: an auto-stop Lambda on a schedule, alerts, a budget.

Day 10 · Terraform CI

GitHub Actions runs fmt, validate and lint on every pull request, with Infracost showing the monthly cost change before anything is applied.

Go-live · FreshTrack

Argo CD deploys FreshTrack with Helm, secrets from OpenBao through External Secrets, HTTPS from cert-manager, basic auth. Then a one-week trial and a clean destroy.
